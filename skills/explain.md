# Explain

1. If the user named a file or folder, start there. Otherwise list the working folder and read the README and the package or build file.
2. Find the entry points (the main script, the routes, the commands) and follow one real path through the code. Read the files; do not guess from their names.
3. Answer in this order: what it is for, in one or two sentences; the main parts and what each does, with file paths; how a typical request or run flows through them; anything surprising a newcomer should know.

Keep it short and concrete. Quote a line only when the exact text matters. If part of the code was not read, say which part.
